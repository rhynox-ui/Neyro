# Neyro Security / Reliability Audit — 2026-10-02

Scope: current `main` codebase, NEARly documentation supplied for the current protocol behavior, wallet custody, trading execution, Rhea routing, NEARly launch/trade integration, Telegram state, persistence, and Cloudflare Worker deployment.

## Remediation status

### Fixed in `audit-hardening-2026-10-02`

1. **NEARly tax awareness — fixed**
   - Neyro now reads immutable `get_tax(launch_id)` data for NEARly tokens.
   - Sell quotes use the post-sell-tax amount that actually reaches Rhea.
   - Buy quotes expose expected/minimum output after the immutable buy tax while preserving Rhea's pre-tax on-chain minimum.
   - Added exact integer arithmetic tests.

2. **Protocol fee freshness — fixed**
   - A price-derived Neyro protocol fee is recalculated immediately before signing.
   - If the fee changed while the quote was waiting, execution is stopped and the user must refresh instead of silently paying a different amount.

3. **Replica-stale slippage settings — fixed**
   - In-memory settings cache is now limited to 5 seconds.
   - A Worker isolate cannot retain an old setting indefinitely.

4. **NEARly creator-share configuration — hardened**
   - `creator_share_bps` is no longer hardcoded.
   - Neyro omits it so the factory's current `creator_fee_share_bps` default applies.
   - This is intentionally not treated as a protocol bug: the current NEARly contract accepts omission and uses the factory default.

5. **Transaction uncertainty / receipt verification — already fixed before this audit**
   - Broadcast hashes are journaled.
   - Timeouts remain unknown until reconciliation.
   - Receipt-level failures and FT balance deltas are checked before reporting a fill.
   - Fees are collected only after a verified fill.

6. **Wallet encryption / row binding — already fixed**
   - AES-GCM v2 uses account-bound AAD.
   - Decryption verifies the key controls the stored implicit account.
   - Production requires persistent storage and the master key.

## Remaining production hardening

### HIGH

7. **Dedicated signer service**
   - Current architecture still decrypts wallet keys inside the Telegram Worker process.
   - A Worker compromise plus the master key would have a large blast radius.
   - Target: isolated signer service, envelope/KMS-wrapped per-wallet keys, independent policy enforcement.

8. **Scoped NEAR function-call keys**
   - Trading should use a scoped access key restricted to approved Rhea/FT operations.
   - Full-access key should be reserved for recovery/withdrawal operations.

### MEDIUM

9. **Cloudflare Queue provisioning**
   - Worker code already supports `NEYRO_TELEGRAM_UPDATES` and a Queue consumer.
   - Production configuration intentionally leaves the binding disabled until the queue is actually created.
   - Provision with:
     `npx wrangler queues create neyro-telegram-updates`
     then enable the producer/consumer binding in `wrangler.jsonc`.
   - Do not enable the binding before the queue exists.

10. **Distributed rate limiting**
   - Current limiter is per Worker isolate.
   - It is useful flood protection, but not a global security boundary.
   - Add Cloudflare Rate Limiting or a durable atomic Postgres/Redis limiter before large-scale public traffic.

11. **Sell-all policy**
   - SELL ALL intentionally bypasses the normal percentage-of-balance limit.
   - Keep this emergency-exit behavior, but make the UI explicitly state that SELL ALL bypasses the normal size limit.

12. **Fee reconciliation / refunds**
   - Unknown fee transactions are reconciled.
   - A fee transaction that definitively fails is recorded as uncollected.
   - Any future automatic fee-refund mechanism should be idempotent and must never refund a fee whose transaction later resolves as collected.

13. **Mainnet integration tests**
   - Add a controlled mainnet test matrix for:
     - no-tax NEARly buy/sell
     - 1–4% buy tax
     - 1–4% sell tax
     - refunded swap
     - RPC timeout after broadcast
     - Rhea registration + swap
     - fee transaction timeout
     - duplicate Telegram confirmation
     - wallet switch between quote and confirmation
     - NEARly launch with/without tax
     - pair launch
